# 学習によるルール獲得ループ — ルール＝意思決定のパラメータという見方

2026-07-08 の設計議論の記録。戦略レポート部門（締切 2026-09-13）の中核素材。

要旨：学習のためにルールで行動空間を枝刈りするのではなく、**ルール（マスク）そのものを意思決定のパラメータとみなし、学習でルール強度を獲得する**。そして **θ を最適化し尽くしてなお残る divergence が、新しいルールを創造すべき地点を指す**。

## 1. 前提：確率的方策はこのコンペではほぼ不要

理論上、ポケカは二人零和・不完全情報ゲームであり、ナッシュ均衡が混合戦略（確率的方策）を要求する余地はある（ポーカーのブラフに相当）。しかしそれは「相手がこちらの方策を知っていて搾取してくる」状況への防御であり、本コンペではその前提が成立しない。

- **相手が静的**。Kaggle ラダーは提出済みエージェント同士の対戦で、相手がエピソードをまたいでこちらの行動分布に適応することはない。固定された相手（相手側が確率的でも）への最適応答は常に決定的方策で達成できる。
- **ポケカはブラフ機構が薄い**。ベット額のような情報操作の手段がなく、行動はほぼ盤面の発展に強制される。「ボスを今は撃たない」といった情報秘匿は決定的な選択で表現でき、確率混合を要しない。
- 実例とも整合する。ptcg-abc（Elo 871）も公開上位 Notebook もすべて決定的ルールベース。

確率性に残る実用価値は**訓練時の探索・平滑化**（ε-greedy、softmax）だけで、デプロイ時は argmax に畳む。現行の `(score, -index)` 辞書式の決定的タイブレークは、divergence mining とデバッグの再現性を支える資産であり、積極的に維持する。

相手手札・サイド落ちの不確実性は決定化サンプリング（PrizeTracker 的な推定）で扱う話であり、出力方策を確率化する理由にはならない。

## 2. 定式化：ルール＝基底関数、強度＝パラメータ

ルールを特徴量（基底関数）、強度をパラメータと見ると、方策は次の形に落ちる：

```
score(s, a; θ) = Σ_r θ_r · φ_r(s, a)        方策 = argmax_a score
```

- **φ_r ＝ ルール述語**（「相手ベンチに進化元がいる」等の条件）— **人間が書く**
- **θ_r ＝ そのルールの強度** — **学習で決める**
- ハードマスク ＝ θ_r → −∞ の極限。レベル別マスク ＝ θ の桁の分離

重要なのは、**現行実装は既にこれを手書き定数でやっている**こと。`LETHAL_BAND = 1_000_000`、敗北駒の `−15000`、R-10 の `−1` —— レベルは既に数値としてコードに埋まっており、辞書式の優先順位は桁の分離として実現されている（正典は [用語とターン手順.md](../planning/用語とターン手順.md)、強度ラベル付きルール集は [ルール抽出_オープン実装.md](../planning/ルール抽出_オープン実装.md)）。つまり「ルールのパラメータ化」は概念の変更ではなく、**既存の定数を変数に昇格させるだけ**である。

分担線はこう引ける：ルールの**実装（述語 φ の記述）までは人間が解析的にできるが、マスクレベル（強度 θ）は解析的に決められない**。そこを学習に委ねる。

## 3. 学習手順：条件付きロジット → ブラックボックス最適化

順番が重要。(a) → (b)。

### (a) 上位プレイヤーエピソードへの条件付きロジット適合

各局面で候補手のスコアに softmax をかけ、上位プレイヤーが実際に選んだ手の尤度を最大化するよう θ を推定する（離散選択モデル、ほぼ凸の教師あり学習）。

- **サンプル効率が桁違い**：自己対戦の勝敗は 1 試合 1 ビットだが、これは **1 手 1 ラベル**。
- これは **divergence mining の損失関数化**そのもの。不一致を目視で掘る代わりに、不一致を最小化する。リプレイ基盤（`scripts/replay_divergence.py`）は既にある。
- softmax は訓練時の平滑化の道具にすぎず、デプロイは argmax で決定的（§1 と整合）。

### (b) gauntlet 制圧度のブラックボックス最適化

(a) で初期化した θ を、`scripts/gauntlet.py` の制圧度（シェア加重勝率）を目的関数に CMA-ES / CEM で微調整する。上位プレイヤー模倣の天井を超えうる一方、次の代償がある：

- **評価ノイズ**：40 試合で ±10pt ブレる → 1 点評価に 80 試合以上。
- **プール過適合**：自前対戦相手プールに最適化される。最終判断は実ラダー A/B（ローカル評価は実ラダー順位を予測しない — ptcg-abc の教訓）。

## 4. 中心テーゼ：残差 divergence ＝ ルール創造の地点

パラメータ化されたルール族には表現力の天井がある。どんな θ でも正しい判断を表現できない局面クラスは、チューニングでは直らない。ただしそれは検出可能で、**θ を最適化し尽くした後に残る divergence が「新しい述語が必要な場所」のシグナル**になる。

したがって全体像は「学習でルールを獲得する」の一方向ではなく、次の**交互ループ**：

1. 述語 φ を書く（人間・解析。divergence レポート起点）
2. 強度 θ を学習で決める（条件付きロジット → gauntlet 微調整）
3. 残差 divergence を測る → 大きい所が次の述語の候補 → 1 へ

一言で言えば：**学習でルール強度を獲得し、その残差でルール本体の必要性を発見する**。マスクの実装は仮説空間の設計であって枝刈りではなく、意思決定の実体は θ にある。

付随する構造的注意：**マスクの誤りは学習では直らない**（誤ってマスクされた好手は候補に残らないため）。訓練時だけマスクを一段緩め（安全マスクのみ）、学習方策がマスク境界の外で何を選びたがるかを観察すれば、マスク自体の検証（レベル設定の妥当性チェック）にも学習が使える。

## 5. 未解決論点（レポートの実験ネタ）

- **最終方策を確率的にするか決定論でいくか**。§1 の論証は決定論を支持するが、実験でしか決着しない。ラダー上での A/B が最終審判。
- **訓練時マスク緩和によるマスク境界の検証**（§4 末尾）をどこまで体系化できるか。
- 条件付きロジットの線形スコアで足りるか、バンド内タイブレークに非線形モデル（GBDT/小 MLP）を足すべきか。

## 6. RL 挿入点の優先順位と時間軸

価値が高く着手コストが低い順：

1. **学習をルール発見ツールとして使う**（divergence mining の延長。デプロイ物は決定的ルールのまま → R-01 のリスクを増やさない）
2. **ルール重み・閾値の最適化**（§3。gauntlet 基盤流用で着手コスト最小）
3. **バンド内タイブレークの残差学習**（ハードマスク・敗北回避・リーサル昇格は安全側の封筒として残し、同バンド内の僅差候補のみ Q(s,a) で並べ替え。`scripts/action_abstraction.py` の ActionChoice が縫い目。推論失敗時はルール順にフォールバック）
4. **状態価値関数 V(s) による 1 手読み**（局面評価は手書きが最も難しく学習の効きが最大だが、`search_begin` 系エンジン API の呼び出しコードが未実装で配管コスト最大。時間プール 600 秒的にはトリガーターン限定推論で収まる — R-23）

時間軸：エージェント提出締切 2026-08-16 →「ルールとデッキを先に成熟、学習は最後」（2026-07-06 方針）に従い 1→2→3 の順、4 は間に合えば。戦略レポート締切 2026-09-13 までに実験結果（§5）を揃える。
