## 配分プラン（このデッキの核。R-05/R-07 の実装形 = ルール型「3. 配分列挙」）

Phantom Dive は「アクティブ200 + ベンチ60 ばら撒き」の複合打点。ターゲット×配分の組合せは
指数的だが、**公式サンプルの `main_option_proc` は「60 で完全に取り切れる相手部分集合」だけを
DFS で列挙する枝刈り**を行う（= counter_indices。半端に載せる配分は列挙しない。HP合計が
残り60を超えた枝は即バックトラック）。各攻撃対象 i（アクティブ or ボス吊り出しのベンチ）×
counter 部分集合についてサイド獲得数とヒューリスティックスコア（prize_count / pokemon_score）で
採点し、最良を plan_a に、「アクティブを攻撃する前提の最良」を plan_b に保持する:

- **plan_a**: ボス吊り出し込みの最良計画。`plan_a.attack > 0` のときボスの指令の価値が 60000 に跳ね、
  吊り出し対象（TO_ACTIVE の相手選択）に +100000
- **plan_b**: 攻撃宣言後の DAMAGE_COUNTER_ANY（6個配分）はこちらを参照
  （配分選択の時点で攻撃対象はアクティブに確定しているため）
- スコアの構造: 取り切り = 50000（リーサルマーカー）/ サイド2以上を先行して取ると残りサイド4以下では
  -1200（R-09 的なペース管理）/ 1枚だけは -300 / 0枚（温存配分）は +1200
- **no_damage_dex** {158 Drednaw, 207 Milotic ex, 330 Sylveon, 345 Crustle}: アクティブ200を0に
  （mt.IMMUNE_TO_EX_ACTIVE と同一集合。ex からの打点無効）
- **no_damage_counter** {28 Poltchageist, 199, 203, 207, 362, 1136} + Mist(11)/Rock Fighting(20) エネ装着:
  ダメカン配置不可。**移植版では DFS の候補からも除外**（サンプルは配置時ガードのみで、プランが
  物理的に不可能な対象を含み得た。リーサル判定の過大評価を防ぐための意図的な改良）

**リーサル判定との接続**: `judge_lethal` をオーバーライドし、
「plan の総サイド（アクティブKO + counter部分集合KO）≥ 自分の残りサイド」かつ
「Phantom Dive を今すぐアクティブで払える（can_main_attack）」なら LETHAL_BAND 昇格
（route "active"、attack_id 154。plan_a.attack>0 ならボス所持・サポート未使用を条件に route "boss"）。
ベンチ経由（退却が必要）の計画は昇格しない。単発KO・他アタッカーは base の judge_lethal に委譲。

## S-7: Phantom Dive「ばら撒き60」の配分探索【2026-07-13 採用・ユーザーとの設計議論】

### 動機（旧配分の構造的な穴）
Phantom Dive は「正面200（アクティブ固定）＋ ベンチにダメカン6個(=60)を配分」。**6個は必ず全部
ベンチに置かれる**（engine 実測: `DAMAGE_COUNTER_ANY` の候補はベンチのみ・remainDamageCounter が
6→1 と強制消化。「置かない」は選べない）。旧 `_main_option_proc` の DFS は「今60で取り切れる
ベンチ部分集合」しか列挙せず、取り切れない残り（毎ターンの大半）では `plan_b["counter"]` が空 →
実配分がヒューリスティック（HP最小×価値）に丸投げされ、**布石・積み上げの概念が皆無**だった。

### 設計（2資源に分解）
- **正面200**: HP≤200 にのみ有効。低HPに撃つと過剰打点（残10に200は190無駄）。ボスで200前後を
  呼ぶ判断で最適化（既存 plan_a のボス釣り出し領域。ばら撒きは正面に乗らないので独立資源）。
- **ばら撒き60**: ベンチのみ。「最小攻撃回数でサイド取り切り」の軽量探索 `_plan_spread` で配分。
  - **取り切り優先**: 6個以内で取り切れるベンチ部分集合をサイド最大で確保（無駄なく分割）。
  - **残りを1体へ布石**: A=置物のベンチKO（次サイクルで取り切りに近づける）/ B=アタッカーを
    正面200圏(≤200)に押し込み（2発以内で届く中型が対象。340級は諦め）。
  - 同点タイブレーク=確実性（ボス消費が少ないルート。R-16 と整合）。相手は静止仮定。

### 重要な実測知見: HPは現物・進化前提は「役割判定」のみ
当初ユーザー決定は「進化前提（相手ベンチを最終進化形のHPで評価）」だったが、**進化前提を全HPに
適用した版は制圧度非改善（80戦 54.8→54.4%）で棄却**。原因: 進化前提が全ベンチHPを膨らませ
（Riolu 70 を Mega Lucario 340 とみなす）、「今の盤面で削る対象」の現物HPを無視し、今殺せる
小型たねを見逃していた。上位ピロットは逆に**小型たねを進化前に現在HPで潰す**（一致率分析でも
human=小型たね / ours=大型アタッカー の不一致が全パターン）。→ **HP・サイドは現物、進化前提は
「アタッカーか＝将来正面に来るか」の役割判定にのみ使う**に切り分けたら制圧度が改善した。

### アタッカー判定（履歴 + 静的補正）
`ATTACKER_IDS_LEARNED` = 対戦履歴からの実測（`scripts/extract_attacker_pokemon.py`、1761
エピソード、「active滞在中にATTACK宣言した試合率≥0.5」で2値化、`research/meta/attacker_pokemon.md`）。
役割はカードスペックからは出ない（Solrock/Fan Rotom は技あるが置物、Fezandipiti は damage=0 だが
狙撃）ため履歴で測る。**HP>120 のみ対象**（≤120 はばら撒き2発で取り切れるので役割判定不要）。
履歴で漏れる Mega Kangaskhan ex(756, 0.49) は `_is_attacker` で `megaEx` 属性を OR して補正。

### 実装
`_final_form`（evolvesFrom 逆引きで最終進化形＝役割判定用）/ `_is_attacker` / `_bench_targets`
（現物HP・現物サイド・進化前提の役割）/ `_plan_spread`（配分計画 {coord: 目標残HP}）。
`_score_counter` の DAMAGE_COUNTER_ANY 分岐が `USE_SPREAD_SEARCH` 時に spread_plan を参照。
`USE_SPREAD_SEARCH` 既定 True、`DRAGA_SPREAD=0` で旧配分に戻せる。リーサル聖域
（`judge_lethal`/`_spread_lethal`）は不変。

（+11.3pt。旧23.3→新30.8% を120戦で再確認・約1.9σ）**。他: kangaskhan +5.0 / chandelure +5.0 /
megastarmie +7.5 / okidogi +5.0 / comfey +5.0。L1 check_agent 合格（623判断・エラー0・10-0）。
**残課題: garchomp -12.5pt（55.0→42.5）が唯一の明確な悪化**。ガブのローテーション戦術への

## 6. 教訓

- **移植は「同じルールが同じ効果を持つ」ことを前提にできない**。ボム版で +1.4 だった同じ
  バンドルが通常版で −2.5。デッキのテンポ状況（UB を撃つ余裕があるか）が符号を決めていた。
- **バンドルで測ると犯人が隠れる**。4件同時 −2.5 の裏で S-0! は +0.4 だった。分解して初めて
  「1件は棄却・3件は無風」が見えた。逆に言えば**バンドルのまま採用/棄却すると、無害な3件を
  巻き添えで捨てるか、有害な1件を混ぜて入れるかのどちらかを必ずやる**。
- **「移植元で効いた理由」を移植先で再検査する**。ボム版の S-0! はダイブ到達の飢餓を直す
  修正だったが、通常版のダイブ到達率は既に 90%（プローブ実測）で飢餓が無かった。**移植前に
  この1本を測っていれば、期待値の見積りを最初から下げられた**。
- **相手役はライブでロードされる = 実験中に動く**（事故 2b）。長時間 A/B では相手を凍結する。
  特に maximin は最弱1セルを直接読むので、相手役の移動が判定をそのまま反転させる。
- **同じセルの数字が測るたびに動くとき、疑うべきは分散だけではない**。今回 marnie は
  36.4→46.2 と動いたが、これはノイズ（SE 1.9pt）では説明できない大きさで、実際に相手が
  変わっていた。**σ で説明できない変動を見たら、まず環境が動いていないかを確認する**。
