# 評価方法（4層ピラミッドとルール採用の判定規則）

作成: 2026-07-08。動機: ルール調整がローカル資産（自作7体プール）への適合に寄りすぎるリスクへの防御。
ptcg-abc も同じ失敗を記録している（ガントレットは既知のラダー結果と矛盾 — 相手ピロットが実上位人間より
弱い。ローカルは回帰検知の物差し、ラダーが唯一の審判 = P-03）。相手が全部自作ピロットの評価だけで
調整すると「自作の癖に勝つルール」が育つ。本書はそれを防ぐ評価の正典。

## 評価の5層ピラミッド（2026-07-10 に L0 を追加。**番号の正典はこの表**）

| 層 | 何を測るか | 道具 | 頻度・位置づけ |
|---|---|---|---|
| **L0 オフライン計算** | 対戦不要の物差し: shadow 一致率・held-out 選択一致率・V(s)/分類器の AUC・較正 | `ab_battle.py --shadow` / `train_value.py` / `fit_theta.py` | リファクタ回帰検知・学習部品の大量ふるい。ほぼノイズなし |
| **L1 不変条件** | クラッシュ・違法手・基盤同期・R-25（ローダー忠実） | `scripts/check_agent.py` | 常時（全変更で必須） |
| **L2 プール対戦** | 回帰検知・相対比較（勝率A/B・シェア加重の制圧度） | `scripts/ab_battle.py` / `scripts/gauntlet.py` | 変更毎。**相手は自作なので絶対値は信じない** |
| **L3 人間アンカー** | 実上位人間との行動一致率（divergence）が**下がらない**こと | `scripts/replay_divergence.py`（ホールドアウト日） | **ルール変更**採用の門番。相手は実プレイヤーの選択 |
| **L4 実ラダー** | 真の強さ。唯一の審判（P-03） | 提出 + `research/ladder/scores.csv` | 泳がせ標準は `提出戦略.md` 準拠 |

- L0→L4 の順に「安いが偏る → 高いが真実」。下の層は上の層の代替にならない。
- 一括実行: `scripts/eval_battery.py`（L1〜L3 を1コマンドで回し `research/eval/<date>_<agent>.md` に記録）。
- **旧番号への注意**: 実験計画 §5（2026-07-09 版）と LEDGER の旧行は「L1=プール / L2=ラダー」の
  3審級番号を使っていた。2026-07-10 に本表へ統一（旧 L1 → L2、旧 L2 → L4 と読み替える）。

## 部品採否（探索・V(s)・θ 等の「部品」）への適用

ルール変更（φ・スコア）と部品採否では、通す層と門番が違う:

| 変更の種類 | 通す層 | 採用条件 |
|---|---|---|
| ルール・スコア変更 | L1 → L2 → L3 →（L4） | **L2改善 ∧ L3非悪化**。L2のみは【暫定】 |
| 部品採否（探索・V・θ） | L0 → L1 → L2 →（L4） | **L2 で +7pt@320試合 ∧ holdoutアーキタイプ非劣化** → L4 で確定 |

- 部品採否で **L3 は門番でなく診断**。部品（探索・学習）は上位人間を超えることを許す層なので、
  一致率の低下は想定内。ただし「部品が変えた手」の divergence レポートは新述語（φ）発見の材料として読む。
- 部品の L2 は **holdoutアーキタイプ**（プールから意図的に外した 2〜3 デッキ。現行 okidogi, lopunny,
  rocket）への非劣化を必須とする（プール過適合の防御。gauntlet `--exclude` / `--only`）。

## 判定規則（スコア変更・ルール変更の採用条件）

1. **採用 = L2 改善 かつ L3 非悪化**。
   - L3 非悪化の目安: ホールドアウト日の一致率がベースライン比 **±3pt 以内**（60試合規模のサンプリング
     ノイズ帯）。**5pt 超の低下**は当該ルールが効く SelectContext のコンテキスト別表で原因を特定する。
2. **L2 のみ改善（L3 未計測 or 悪化）は【暫定】**。当該ルールを `ルール抽出_オープン実装.md` /
   デッキ設計md に【暫定】タグで記録し、L4（ラダー実測）まで確定に昇格しない（P-09）。
3. L4 に出す前に**成功基準を先に書く**（事後正当化の防止）。例:「2〜3日・50戦で スカウト枠の
   現行値 ±50 Elo を上回る」。泳がせ時間・入替判断は `提出戦略.md` の表に従う。

## 時間ホールドアウト（P-10）

- divergence 調整に使った日のエピソードで検証しない。**調整日 ≠ 検証日**。
- デッキ設計md の divergence 節に「調整日 / 検証日」を明記する。
- 検証日は原則**調整日より後の日**（メタの前進方向での汎化を見る）。Daily Episodes データセットは
  **翌日 00:08 UTC 頃**に公開されるため、当日調整→当日検証はそもそも不可能。未公開の間は
  調整日と異なる直近日で代用し、公開後に本命日で再計測する。
- 置き場: `downloads/episodes/<date>/`（250件標準）。取得は `scripts/download_episode_sample.py`。

## ピロットスタイル多様性（P-11）

- 同一相手デッキを **tuned（自作チューン済み）/ generic（GenericPolicy）/ frozen（凍結旧版）** の
  3スタイルで差し替えて勝率のブレを見る: `scripts/gauntlet.py --styles tuned,generic,frozen`。
- スタイル間で勝率が **±15pt 超**ブレるマッチアップは「特定ピロットの癖に勝っている」疑い。
  そのマッチアップの勝率を根拠にしたルールは【暫定】扱いにする。
- frozen が無いデッキは skip（凍結資産は `experiments/frozen_agents/`。P-06 で蓄積していく）。

## ワークフロー（スコア変更の標準手順）

```
変更 → eval_battery（L1/L2/L3）→ 採用判定（L2改善 ∧ L3非悪化）→ 【暫定】は L4 で確定
```

- レポートは `research/eval/<date>_<agent>.md` に自動出力。結論（確定/暫定/棄却）は
  デッキ設計md と PROJECT_DIARY に転記する。
