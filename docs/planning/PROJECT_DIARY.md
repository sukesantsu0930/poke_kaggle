- **rollout 棄却（実測）**: 終局 rollout はポケカで飽和。診断で generic相手=全勝(1.0)/専用相手=
  全敗(0.0)、専用の means≈0.0 が gauntlet 実測42〜55%と矛盾＝実対戦を反映しない
- **V**: 全体戦略の本命（Phase 5）。教師は MC（各盤面に試合の勝敗0/1→回帰で滑らかに）。配分には
  解像度不足で不向き
- **CFR 棄却**: 情報集合爆発（相手手札×山60!×履歴）でタブラー不可能＋§7.1 で Nash 否定済み
- 配分＝算数なので軽量プランナー。目的関数の重みは勝率(gauntlet)で較正

   手書きの帯構造が崖で、θ では越えられないか、越えると全局面一律にカテゴリ順序が反転する。
   さらに実際に選ばれた決定の **64% が top-k 24 reason の対象外**だった。

**定性的結論**: θ は reason 単位の一律シフトしかできず、**軌跡の局所的変更が構造的に不可能**。
探索の分解能は φ の粒度で決まる。「θ 最適化 → 残差が新述語を指す」（中心テーゼ）は順序が逆で、
**φ を十分細分化して初めて θ 最適化が意味を持つ**疑いが強い。θ の CEM は現行 φ のままでは棚上げ。

### 学習アーキテクチャの設計議論 → 「場のモデル」の確定（正典化: 実験計画 §7）

Phase 4（CEM）をサーバーで回す直前に、**相手プールをどう定式化するか**を詰めた。結論と根拠は
[エージェントアーキテクチャと実験計画.md](../strategy/エージェントアーキテクチャと実験計画.md) §7 に正典化。要点のみ:

- **解概念は Nash ではない**。「静的」には (a) 相手の方策が適応しない＝**真**、(b) デッキ構成が
  変わらない＝**偽**（Archaludon 40.7%→4.9%/4日）の二義があり、混同していた。Nash が解になるのは
  相手が**こちらに**最適応答するときで、その前提は無い。実脅威は**環境分布の漂い**であり、
  これは均衡ではなく**分布シフトへのロバスト最適化**の問題。
- **self-play は採らない**。self-play が対処するのは「相手の方策の強化」軸で、実脅威の
  「デッキ構成の入替」軸と噛み合わない。加えて (1) 場が現実（他人の手書き、Elo 871 級）を超える、
  (2) 両側同θでミラー勝率が50%定数化し**シェア1位デッキの信号が消える**、(3) 非定常化で CEM が壊れる。
- **プールは「私たちのベスト」ではなく「締切時点の実ラダーの予測モデル」**。これが唯一の設計原理。
  強さドリフトを織り込むなら field CSV に `(1−p)×θ=0 行 + p×学習済み行` として**明示的に書く**（現在 p=0）。
- **θ は資産でなく消耗品**（1本2〜3.5時間、ウォームスタート1〜2時間）。「重要デッキほど後回し」ではなく
  「今取り、8/10〜11 に最新 field で取り直す」。**真のボトルネックは φ を書くことと L2 の壁時計**。
  プールへの新デッキ追加は学習不要（デッキリスト + `generic` 操縦の1行）なので、最終週の新アーキタイプも入る。

### 行動空間削減の方針

- GUIの選択肢削減は、後段のエージェント開発における行動空間削減の土台として扱う。
- 同質な行動だけを畳む。見た目が似ているだけの行動は削除しない。
- 現時点では、同じ基本エネルギータイプを同じポケモンへつける選択肢だけを代表1つに畳む。
- 付け先が違う場合、基本エネルギーのタイプが違う場合、特殊エネルギーのカードIDが違う場合は別行動として残す。
- 手札から使う同名カードは、単一選択の場面では代表1つに畳む。
- 複数枚を同時に選ぶ場面では、同名カードでも必要枚数を選べなくなるため現時点では畳まない。
- 共通ロジックは `scripts/action_abstraction.py` に置き、GUIだけでなく将来のAgentからも参照できる形にする。
- 回帰テストは `tests/test_action_abstraction.py` に置く。
